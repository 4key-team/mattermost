# Принудительное использование мобильного приложения (блокировка веб-доступа)

**Дата:** 2026-06-04
**Ветка:** `feature/force-mobile-app`

## Проблема и цель

В мобильном приложении Mattermost уже есть защита от скриншотов чата. В вебе (браузер,
десктоп-приложение) такой защиты технически нет. Чтобы закрыть сценарий утечки через
скриншоты, нужна возможность **полностью запретить не-администраторам пользоваться
веб-клиентом** и принудить их перейти в мобильное приложение.

Решение: новый тумблер в системной консоли. При его включении не-администраторы при заходе
в веб-клиент видят полноэкранное **неотключаемое** окно с инструкцией скачать приложение и
ссылками на сторы. Чат за окном недоступен.

## Ключевое наблюдение

Мобильное приложение Mattermost — нативное (React Native) и **не исполняет этот веб-код**.
Значит, веб-приложение запускается только в браузере или десктоп-приложении (Electron) —
оба мы и хотим заблокировать. Поэтому определять платформу не требуется: достаточно
условия «настройка включена И пользователь не системный админ». Мобильный клиент
автоматически не затрагивается.

## Объём (что делаем)

1. **Серверная настройка (Go).** Новое булево поле `*bool` `ServiceSettings.ForceMobileApp`
   в `server/public/model/config.go`.
   - По умолчанию `false`, инициализация в `(*ServiceSettings).SetDefaults()`.
   - Прокидывается в клиентский конфиг в `server/config/client.go`
     (`GenerateClientConfig`) как строка `"true"/"false"`, доступная всем
     **залогиненным** пользователям.

2. **Тумблер в системной консоли.** Запись `type: 'bool'` с ключом
   `ServiceSettings.ForceMobileApp` в
   `webapp/channels/src/components/admin_console/admin_definition.tsx`, раздел
   **Site Configuration**. Label + help_text. Строки добавляются в
   `webapp/channels/src/i18n/en.json`.

3. **Клиентский гейт (React).** Новый компонент `ForceMobileAppGate`, смонтированный в
   layout залогиненного пользователя (`webapp/channels/src/components/logged_in/logged_in.tsx`),
   чтобы страницы входа/регистрации оставались доступны. Рендерит оверлей, когда
   одновременно:
   - `getConfig(state).ForceMobileApp === 'true'`, **и**
   - `isCurrentUserSystemAdmin(state) === false`.

4. **Окно (оверлей).** Полноэкранный `position: fixed` контейнер с высоким z-index, **без
   кнопки закрытия**, без реакции на ESC/клик по фону:
   - логотип/иконка Mattermost;
   - заголовок: «Доступ через браузер ограничен»;
   - текст-инструкция: скачайте приложение и войдите, указав адрес этого сервера
     (`window.location.origin` показываем как подсказку, какой сервер вводить);
   - две кнопки-ссылки: App Store и Google Play;
   - все тексты — через i18n (`react-intl` / `en.json`).

5. **Константы ссылок (хардкод).** Официальные ссылки Mattermost, заданы константами в коде:
   - iOS: `https://apps.apple.com/app/mattermost/id1257222717`
   - Android: `https://play.google.com/store/apps/details?id=com.mattermost.rn`
   - Название приложения: «Mattermost».

## Поведение

- Оверлей перерисовывается при каждом заходе/обновлении страницы, пока настройка включена.
- Системные администраторы видят веб-клиент как обычно (исключение только для системных
  админов; админы команд — нет).
- При выключении настройки оверлей исчезает у всех без перезахода (реактивно из конфига).
- Гейт смонтирован только в залогиненной зоне, поэтому экраны логина/регистрации остаются
  рабочими; блокировка появляется после аутентификации не-админа.

## Архитектура / границы компонентов

- **Сервер:** поле конфига + дефолт + сериализация в клиентский конфиг. Зависимости — только
  существующие механизмы `model.Config` и `config.GenerateClientConfig`.
- **Admin UI:** декларативная запись в `admin_definition.tsx` + i18n-строки. Зависит от
  значения конфига, рендерится штатным `BooleanSetting`.
- **`ForceMobileAppGate` (контейнер):** читает `getConfig` и `isCurrentUserSystemAdmin` из
  Redux, решает — показывать ли оверлей. Не содержит вёрстки самого окна.
- **`ForceMobileAppModal`/оверлей (презентационный):** только вёрстка окна и ссылки. Не знает
  про Redux. Получает `siteUrl`/тексты пропсами или берёт `window.location.origin`.

Такое разделение позволяет тестировать логику показа отдельно от вёрстки.

## Тестирование

- **Сервер:** unit-тест на `SetDefaults` (дефолт `false`) и на присутствие `ForceMobileApp`
  в результате `GenerateClientConfig`.
- **Клиент (гейт):** тесты, что оверлей показывается при `ForceMobileApp==='true'` и
  не-админе; скрыт, если настройка выключена; скрыт для системного админа.
- **Клиент (окно):** smoke-тест рендера, наличие двух ссылок на сторы с правильными URL и
  отсутствие кнопки закрытия.

## Сознательно НЕ делаем (YAGNI)

- Определение платформы (браузер/десктоп/мобайл) — не нужно, см. «Ключевое наблюдение».
- Серверную блокировку REST API по User-Agent — ненадёжно (мобайл использует тот же API).
- Настраиваемые в консоли ссылки/тексты — по решению зашиты в код.
- Исключения для админов команд — только системные админы.

## Известное ограничение

Это **клиентская UI-блокировка**. Технически подготовленный пользователь может её обойти
(отключить JS, обращаться к REST API напрямую), поэтому 100%-ной защиты от скриншотов в
вебе она не даёт. Она закрывает обычный пользовательский сценарий, а не угрозу со стороны
мотивированного злоумышленника.
